# 最终图片生成工作流

这个文档用于避免 Skill 停留在“模板/提示词方案”，确保用户要图文时，最终得到的是图片文件。

## 核心原则

- 用户说“生成图文”“开始生成”“做成小红书图片”时，最终交付物是图片。
- 完整图文项目必须先用苏格拉底提问法问 10 个问题，再做规划和出图。
- 提示词是生成记录，不是最终产物。
- 默认先生成 1 张视觉确认图，再批量生成整套最终图。
- 视觉确认图必须是接近最终视觉的图片，不是线框、模板或说明页。
- 用户确认视觉方向后，再生成 6-8 页完整图片。

## 默认流程

1. 先用苏格拉底提问法问 10 个问题，问清用户需求。
2. 用户回答后，输出回答摘要与生成假设。
3. 作为视觉导演，输出风格判断报告、多页图文规划和逐页视觉规划。
4. 建立统一视觉母版。
5. 生成 Page 01 封面或关键内页样例图 / 视觉确认图。
6. 等待用户确认。
7. 用户确认后，生成整套最终图片。
8. 保存图片到项目目录。
9. 检查所有图片比例和视觉一致性。
10. 输出图片路径、发布文案和自检清单。

## 视觉确认图

视觉确认图默认使用封面，因为封面最能验证：

- 画幅比例。
- 主风格。
- 色彩令牌。
- 标题安全区。
- 主视觉方向。
- 卡片/线条/图标语言。
- 页码或角标位置。

如果项目是教程、产品详情页、截图改造或商业提案，也可以选择最关键的内页作为确认图。

## 用户确认点

生成确认图后，向用户确认：

- 风格气质是否对。
- 画面冲击力是否够。
- 信息密度是否合适。
- 色彩是否符合预期。
- 是否继续生成整套。

不要在用户确认前批量生成全部页面，除非用户明确说“不用确认，直接生成全套”。

## 最终图片保存规则

建议命名：

```text
generated/[topic-slug]/page-01.png
generated/[topic-slug]/page-02.png
generated/[topic-slug]/page-03.png
...
```

输出时必须报告：

- 文件夹路径。
- 每张图片路径。
- 图片尺寸。
- 比例检查结果。

## 可选 Atlas Cloud provider

默认使用当前环境已有的图像生成工具。只有用户明确要求 Atlas Cloud，或设置
`XHS_IMAGE_PROVIDER=atlas` 时，才使用 Skill 目录内的 `scripts/atlas-image.mjs`：

1. 把统一视觉母版和本页提示词完整写入 UTF-8 prompt 文件。
2. 先生成 1 张视觉确认图，用户确认后再逐页生成。
3. 默认使用 `2592*3456` 的严格 3:4 竖版 PNG。
4. 每页保留同名 `.prompt.txt`，用于复现和返工。
5. 生成失败或下载结果不是 PNG 时立即停止，不进入下一页。

Atlas Cloud 路径只做 prompt-matched 生成，不附加本地参考图。需要参考图约束时继续使用支持参考图输入的现有工具，不能假装已完成 image-reference 匹配。

## 中文文字策略

如果图像模型生成中文容易乱码，优先生成：

- 高质量视觉底图。
- 清晰标题安全区。
- 正文占位区。
- 可后期叠加的卡片和模块。

但仍要交付图片，而不是只交付提示词。

可说明：

```text
这版是最终视觉底图，中文正文建议后期叠加，避免模型生成乱码。
```

如果用户要求图片中直接包含中文，则生成时应尽量放大文字、减少文字数量，并在审查中标记中文可读性风险。
